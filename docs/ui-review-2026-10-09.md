# Customer portal visual review — 2026-10-09

## Scope and verification boundary

The deployed 0.5.11 customer portal was inspected in the live Chrome browser after a secure account-owner sign-in. All eight available routes were visited. Screenshots, visible DOM, accessibility state and rendered dimensions were used to review pages, safe confirmations, disclosures and result controls. The live page loaded the expected 0.5.11 customer styles and scripts.

**The browser viewport was fixed at 1363 × 936 CSS pixels, device pixel ratio 1.** Its supported controls exposed no viewport resize or device emulation, and a zoom shortcut did not change the dimensions. The phone media query `(max-width: 640px)` did not match; orientation was landscape. Consequently, this is a live general UI review plus a source-level portrait responsive audit, **not a completed iPhone SE browser test**. No rendered 375 × 667 or 320 × 568 result is claimed. Dark mode was observed; light mode was reviewed through shared CSS tokens and selectors only.

The authored 0.5.12 changes have not been deployed or rendered in the live browser. Independent source review checked the JavaScript/CSS integration. No local app, build, project verification script or tests were run, as requested. Final portrait and on-screen keyboard verification remains with the owner after deployment.

## Owner portrait verification after deployment

Use Chrome responsive mode at **375 × 667** and **320 × 568**, portrait, and also an actual phone with its keyboard open. Hard-refresh after static deployment completes. Review light and dark mode if both are used.

1. Open each of the eight routes from a previously scrolled page. Its heading should appear first; long values must wrap without horizontal panning. Expand/collapse the phone navigation and reach its last item.
2. Open Watchers → Actions. Check that the complete menu fits inside the record card. Open both existing and blank editors; inspect the header, footer, regional options, trigger input and every escalation level without submitting changes.
3. Focus the bottom recipient input with the phone keyboard open. Scroll all fields and reach Close and the Publish/Save footer. Dismiss a native select with Escape without losing the editor.
4. Open Check Status. Scroll the entire regional and notification timeline; long recipient addresses must remain inside the panel. Verify header padding and Close remain usable.
5. Open View Results from Overview, Watchers and both kinds of archive. Review matched, changed, incomplete and outage results already present. Open all three device views, select regions, expand technical details, toggle overlays and check the evidence heading stays below the sticky header. Test tab navigation with Left/Right/Home/End and modal Tab/Shift+Tab.
6. Review archive stack/detail widths and the local no-match filter. Review report selectors and completed/expired rows without generating anything.
7. Open and cancel Delete, Remove member, Revert, plan-change and account-closure confirmations. Verify wrapped headings, quote details, reason field and both buttons on the shortest viewport. Do not submit these actions for a style check.
8. Review profile fields and country/province pickers, all plan cards and transaction references. Confirm one input per profile row, comfortable touch targets and reachable lower content.

Remaining verification gaps are actual phone-width rendering, keyboard/safe-area behavior, light-mode rendering, WebGL globe rendering and UI states absent from the signed-in account. These are not reported as passing.
