# Consolidated audit change register — 10 October 2026

This register consolidates the complete **AWS Architecture and Financial Controls** audit and **PCI DSS / GDPR / WCAG Readiness** audit supplied for release **0.5.12**, including the financial design in sections 5–14 and the complete WCAG 2.2 A/AA review matrix. The new source snapshot is **0.5.13**. The original audits describe the earlier baseline and remain historical evidence; their statement that recommendations were not implemented does not describe this later source snapshot.

The work in this session was passive source review, source editing and documentation. **No application execution, automated tests, dependency installation, build, browser/assistive-technology session, payment, deletion, deployment or live AWS operation was performed.** Source changes need owner-operated validation and deployment. This register is not a PCI attestation, GDPR compliance determination, accessibility conformance report or accuracy/cost guarantee.

## Status meanings

| Status | Meaning in this register |
| --- | --- |
| Source implemented | The specified correction is present in the source. It is not a claim of deployed behavior or successful verification. |
| Partial | Identified source corrections are present, but material engineering or operating work from the finding remains. |
| Deferred | The requested capability/evidence has not been delivered in this session. |
| Owner decision | Legal, commercial, financial, security or capacity facts must be approved before implementing that part. A decision can coexist with a partial source correction. |

Every status has **verification deferred** unless expressly described as a passive source observation. Tables distinguish a narrow implemented correction from the larger finding. Related findings intentionally overlap rather than counting the same change as separate completed features.

## Architecture and release boundaries

The existing static public/customer/steward surfaces, separate identity pools, tenant authorization, regional queue protocol, disposable browser profiles, DNS-pinned egress, immutable capture configuration, regional evidence binding, credit accounting and comparison/incident rules are retained. The queue protocol remains version 1 and the price catalogue remains `2026-09-capture-credits-usd-v1`. Capacity deferral is a platform scheduling result; it must not create a target outage or consume new capture credits. Result aggregation, run deadlines, payment reconciliation, notifications and erasure remain essential work.

The source still uses the global coherent DynamoDB compatibility adapter for several billing, notification, report-quota, closure, maintenance and steward commands. Bounded writes and a few direct reads do not remove that global read/contended revision limit. No new cost dashboard, near-live financial ledger, rolling cost forecast or dollar governor was built.

Use [release notes](release-notes-0.5.13.md), [deployment](deployment.md), [architecture](architecture.md), [known limitations](known-limitations.md), [data lifecycle](data-lifecycle.md), [privacy decisions](privacy.md), [accessibility](accessibility.md), [secret rotation](secret-rotation.md) and [dependency/release evidence](documentation.md#deployed-dependency-and-release-evidence) alongside this register. Preserve private environment values, the owner subject, deployment principal, staging allowlist and existing billing/provider inputs when adopting the source snapshot. The route/resource inventory was regenerated from the final checked-in CloudFormation with the documentation-only extractor. The retained JSDoc/visual atlas remains a predecessor snapshot; regenerate the full owner documentation before publishing it as current. None of these references proves deployment.
